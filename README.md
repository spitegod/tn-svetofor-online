# Светофор систем ТЕХНОНИКОЛЬ

Веб-сервис для ведения распоряжений, классификации строительных систем ТЕХНОНИКОЛЬ и сравнения изменений между версиями данных.

Сервис объединяет сведения из импортируемых Excel-таблиц с общими метаданными, которые парсер получает с [nav.tn.ru](https://nav.tn.ru): ссылками на системы, типами, изображениями категорий и характеристиками.

## Возможности

- ведение нескольких распоряжений с независимыми наборами систем;
- создание распоряжения из одного XLSX-файла с листами `Таблица 1` и `Таблица 2`;
- отдельный импорт и экспорт Excel-таблиц в ручном режиме;
- отображение добавленных систем и изменений классов относительно предыдущего распоряжения;
- фильтрация по типу строительства, типу системы, классу, куратору и характеристикам;
- каскадные фильтры на основе характеристик с `nav.tn.ru`;
- сравнение произвольного количества распоряжений с изменением их порядка через drag-and-drop;
- комментарии и вложения к системам, включая историю документов;
- ручной и автоматический запуск парсера;
- прогресс, журнал текущего запуска и история запусков парсера;
- настройка периодичности, числа обработчиков, таймаутов и повторных попыток.

## Страницы

| Страница | Назначение |
| --- | --- |
| Изменения | Сводка и таблица изменений относительно предыдущего распоряжения |
| Список систем | Каталог систем выбранного распоряжения, поиск, фильтры и добавление в сравнение |
| Классификация | Карточки систем и каскадная фильтрация по характеристикам с `nav.tn.ru` |
| Сравнение | Сопоставление классов систем между несколькими распоряжениями |
| Настройки | Парсер, распоряжения, импорт и редактирование таблиц, комментарии и документы |

## Откуда берутся данные

Данные распоряжений и сведения парсера хранятся раздельно:

- таблица 1 содержит изменения классов систем;
- таблица 2 содержит шифр, название, класс и куратора системы;
- таблица 3 содержит комментарии и прикреплённые документы;
- парсер хранит общий для всего сервиса каталог `nav.tn.ru` — типы систем, изображения, ссылки и пары `характеристика → значение`.

Основной входной формат — один XLSX-файл: первый лист импортируется как таблица 1, второй — как таблица 2. Новое распоряжение получает название исходного файла без расширения. Отдельный импорт каждой таблицы доступен в настройках как резервный ручной сценарий.

Парсинг не привязан к конкретному распоряжению. При выдаче каталога backend связывает общие данные парсера с системой по нормализованному названию, а frontend формирует из характеристик доступные фильтры и их счётчики.

Импорт распоряжения не ждёт сетевых запросов к `nav.tn.ru`: ссылка и тип строительства берутся из уже собранного общего каталога. После следующего успешного ручного или автоматического запуска парсера обновлённые метаданные становятся доступны всем распоряжениям.

## Быстрый запуск

### 1. Подготовка PostgreSQL

Создайте пользователя и базу данных. Названия и пароль можно выбрать свои:

```sql
CREATE USER tn_svetofor WITH PASSWORD 'change_me';
CREATE DATABASE tn_svetofor_online OWNER tn_svetofor;
```

Отдельно применять миграции не требуется: backend последовательно применяет версионированные транзакционные миграции при запуске и хранит их состояние в `schema_migrations`.

### 2. Запуск backend

```bash
cd backend
cp .env.example .env
```

Укажите созданного пользователя в `backend/.env`:

```dotenv
HTTP_ADDR=:8080
DATABASE_URL=postgres://tn_svetofor:change_me@127.0.0.1:5432/tn_svetofor_online?sslmode=disable
```

Приложение читает переменные окружения, поэтому перед запуском экспортируйте значения из файла:

```bash
set -a
source .env
set +a
go run ./cmd/server
```

Проверка backend:

```bash
curl http://127.0.0.1:8080/api/health
```

Ожидаемый ответ:

```json
{"status":"ok","time":"..."}
```

### 3. Запуск frontend

В отдельном терминале:

```bash
cd frontend
cp .env.example .env
npm ci
npm run dev
```

После запуска доступны:

- frontend — [http://127.0.0.1:5173](http://127.0.0.1:5173);
- backend — [http://127.0.0.1:8080](http://127.0.0.1:8080);
- health check — [http://127.0.0.1:8080/api/health](http://127.0.0.1:8080/api/health).

В режиме разработки Vite перенаправляет запросы `/api` на `http://127.0.0.1:8080`.

## Переменные окружения

### Backend

| Переменная | Значение по умолчанию | Описание |
| --- | --- | --- |
| `HTTP_ADDR` | `:8080` | Адрес HTTP-сервера |
| `DATABASE_URL` | обязательна | Строка подключения к PostgreSQL; приложение не запускается без неё |

### Frontend

| Переменная | Значение по умолчанию | Описание |
| --- | --- | --- |
| `VITE_API_BASE_URL` | `/api` | Базовый URL backend API |

Для развёртывания frontend и backend на разных доменах задайте абсолютный `VITE_API_BASE_URL` перед сборкой.

## Основные группы API

| Путь | Назначение |
| --- | --- |
| `/api/health` | Проверка работоспособности backend |
| `/api/orders` | Управление распоряжениями |
| `/api/orders/import` | Создание распоряжения из XLSX с двумя листами |
| `/api/classification-changes` | Таблица изменений классов |
| `/api/system-catalog` | Каталог систем и таблица 2 |
| `/api/system-documents` | Комментарии, сравнение и вложения |
| `/api/nav-parser` | Состояние, настройки и история парсера |
| `POST /api/nav-parser/runs` | Ручной фоновый запуск парсера |
| `/api/nav-system-types` | Изображения типов систем |
| `/api/comparison/export` | Экспорт сравнения распоряжений |

## Git workflow

Разработка ведётся через короткоживущие ветки:

- `feature/*` — новая функциональность;
- `fix/*` — исправления;
- `hotfix/*` — срочные исправления;
- `docs/*` — документация;
- `chore/*` — технические задачи.

Подробные правила находятся в [docs/git-workflow.md](docs/git-workflow.md).
